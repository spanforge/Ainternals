# AI TCO calculator implementation evidence

Local route: `/tools/ai-tco-calculator`. App version `0.4.0`; financial model `workbook-v1.0`.

## Price Watch integration

The user explicitly authorized extending the original manual-only pricing boundary. `/tools/ai-tco-calculator/pricing` is a read-only, no-store catalog endpoint using the existing official provider loader and cache. It returns public model rates and billing tiers, with source-document excerpts omitted. It accepts no scenario payload. The client reuses `estimateModel` for context, processing, region, period, cache-write and freshness checks. Model-only handoff URLs carry public model/billing choices, never financial workload assumptions.

Linked mode requires USD and acknowledgment that attempted-task tokens describe one billed request. Multi-call or mixed-size workflows require verified blended manual rates. Effective input rates for Moonshot include mandatory cache writes and are labeled. Changing tokens re-evaluates the matching tier locally. Missing, stale, expired, invalid, ambiguous and out-of-capacity pricing pauses linked results and export until corrected or detached. Required rates and provenance are read-only while linked. Non-model operating costs remain user assumptions. Annual token-price change remains a scenario assumption, not a provider forecast.

Exports contain all 33 effective inputs and source provenance. Importing preserves these historical rates in manual snapshot mode; it never silently fetches and replaces prices. Reset restores original illustrative defaults. The source financial model remains `workbook-v1.0`.

The full user guide is at `/tools/ai-tco-calculator/user-guide`. Its 33 entries in `lib/tco/field-guide.json` supply both inline expandable help and the standalone guide. Each entry explains meaning, purpose, expected input, information source, example, affected results, common mistakes and zero/off behavior. Guide search stays in browser memory; printing includes all 33 entries even when a search is active. Only the display grouping and explanatory wording changed; source input order and financial behavior remain unchanged.

## Source and verification

- `tests/fixtures/tco-workbook.json`: original OOXML cell values and formulas, with workbook SHA-256. No cached calculated values are used.
- `tests/tco-reference.ts`: independent limited interpreter for source Excel formulas. Supports references, ranges, arithmetic, comparisons, SUM, lazy IF and IFERROR. It does not use eval or application financial logic.
- `tests/fixtures/tco-golden-defaults.json`: retained full-precision default output fixtures generated by that independent interpreter.
- `workbook-traceability.md`: every one of the 174 formula cells mapped to its application projection. Field order maps the 33 defaults to Inputs B5:B37.
- `parity-report.json`: generated regression results. All 174 formula outputs are checked across 58 scenarios: defaults, all 16 scaling combinations, success/recovery boundaries, zero-volume/success, token-price changes and each individual input.
- `browser-qa-report.json`: local Chrome checks for form labels, live edits, errors, baseline, tabs, JSON round-trip, malformed files, print/PDF, mobile overflow, network requests and browser storage.

The default annual totals are independently corroborated with Decimal arithmetic: Year 1 `139708`, Year 2 `140223.6`, Year 3 `172135.26`; three-year total `452066.86`. For n = year − 1, recurring subtotal = attempts × 0.019 + 6000 × 1.05^n × 1.2^n + 18000 × 1.05^n + attempts × 0.65 × 1.05^n. Annual total = subtotal × 1.1 + 25000 in Year 1 only. These terms independently group the published workbook defaults; they are not the app implementation.

## Source discrepancy

BRD §11 says 31 populated model lines per year. The actual workbook has **33**: rows 5–9, 11–22, 24–30 and 32–40. All 33 are implemented, displayed and tested. The source workbook row 35 baseline and row 39 PV baseline are zero when disabled; only rows 36 and 40 become blank, while dashboard comparisons display `n/a`.
